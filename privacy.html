Privacy policy

This policy describes how SPS Master Control accesses and handles Google user data. The application is a private, owner-operated Windows desktop tool and is not offered as a public service.

At a glance

  • No public accounts
  • No advertising
  • No sale of data
  • No SPS cloud database
  • Owner-controlled storage

1. Scope

This policy applies to Google data accessed by SPS Master Control and to this public information website. The website contains no sign-in, forms, application analytics, advertising, or tracking code. GitHub may process basic hosting information under its own privacy terms because it hosts these pages.

2. Google permissions

SPS Master Control uses two separate Google authorization profiles:

  • Read-only authorization for Google Drive metadata, Google Sheets, and Apps Script projects. It supports inventory, integrity checks, drift checks, backup preparation, and recovery evidence.
  • Privileged development authorization for guarded DEV/LAB backup and recovery operations involving Google Drive, Google Sheets, Apps Script projects, and Apps Script deployments. It is stored separately and is used only after the owner initiates an operation and the application’s authorization and safety checks allow it.

The current “Read my spreadsheets” action reads only resources named by the installed registry. It requests file metadata and spreadsheet structure without requesting spreadsheet cell contents. Other explicitly initiated engineering workflows may read spreadsheet data or Apps Script source when that information is required for validation, backup, or recovery.

3. Data accessed

Depending on the owner-initiated operation, the application may process:

  • Google Drive file identifiers, names, types, timestamps, locations, ownership and permission-related metadata;
  • Google Sheets identifiers, titles, structure, formatting, native objects, formulas, and cell data;
  • Apps Script project identifiers, files, source, versions, deployments, and related metadata;
  • Google OAuth authorization records needed to request and renew access.

4. How data is used

Google data is used only to show the owner what the application can verify, compare registered SPS resources with accepted evidence, create owner-requested backups, support controlled recovery, and record the outcome of those operations.

Google user data is not sold, rented, used for advertising, used for unrelated profiling, or used to train general-purpose artificial intelligence models. SPS Master Control does not send Google user data to an SPS-operated cloud service.

5. Storage and retention

Google OAuth client and token files are stored in the owner’s private SPS folder on the owner’s computer, outside the replaceable application version. The public website does not receive or store them.

Owner-requested operations may create local reports, integrity evidence, backup catalogues, recovery records, or backup copies in the owner’s Google Drive. Their retention is controlled by the owner’s installed SPS policies and the owner’s Google account. There is no publisher-operated server copy.

6. Sharing and transfers

The desktop application communicates with Google’s authorization and API endpoints to perform the operation the owner requested. It does not disclose Google user data to advertisers, data brokers, or unrelated third parties.

Use of information obtained from Google APIs follows the Google API Services User Data Policy, including its Limited Use requirements.

7. Security

The Google authorization flow opens Google’s own consent page in the system browser, uses PKCE and a local loopback response, and sends OAuth credentials only to Google’s registered endpoints. The read-only and privileged authorizations use separate token files. Application safety checks and environment boundaries remain independent of Google consent.

No security system eliminates every risk. The owner can review or revoke SPS Master Control access from the Google Account permissions page.

8. Owner choices

The owner chooses whether to authorize Google access and when to initiate an operation. Revoking access prevents the affected authorization from obtaining new Google access tokens. Local evidence and Google Drive backups remain under the owner’s control and are not automatically represented as deleted by revocation.

9. Changes and contact

This policy will be updated if the application’s Google access or data handling changes. The current support contact is the address shown on the SPS Master Control Google consent screen.
